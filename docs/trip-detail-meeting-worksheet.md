# Trip Detail Page — Meeting Worksheet

Working session with the copywriter to decide what's actually in scope for the new rockbusters.net **Trip Detail page** (the page for one specific trip with concrete dates), and **in what form** each section should take.

**Reference wireframe:** `salzburg-shred-safari.html` (in this folder).

A separate worksheet — `trip-category-meeting-worksheet.md` — covers the **Trip Category / Program landing page** (the page for a recurring camp with multiple dates underneath), built from `rockbusters-performance-camp.html`. The two page types share most sections, but the program-level page has its own shape for the curriculum and date-comparison content.

---

## How to use this worksheet

For each section, make two decisions and capture anything notable in **Notes**:

- **Scope** — is this section in or out of v1?
  - **Keep** — ship it as the wireframe shows.
  - **Trim** — keep the section but cut some sub-elements (note which in **Notes**).
  - **Drop** — remove the section entirely from the page.

- **Form** — how rigid is the content shape on the page?
  - **Structured** — fixed sub-shape the copywriter fills into a template (e.g. *"5 day cards: image · headline · description · 4 tags · time schedule"*). Easier to lay out consistently.
  - **Free-form** — a rich-text block the copywriter writes freely. More flexible, harder to design strong consistent layout.
  - **Mixed** — some sub-elements structured, some free-form.

If a sub-element list is shown for a section, mark **Form** for the section as a whole — unless something specifically diverges, which goes in **Notes**.

## Cross-cutting questions for the meeting

These don't fit inside any one section, but worth a few minutes at the end:

- **Section ordering — is it fixed?** Does every Trip Detail page render the kept sections in the same order, or can it vary per trip?
- **N-day flexibility.** The wireframe is 5-day; trips have varying lengths. The Day-by-Day Itinerary structure needs to support 1 to N days cleanly.
- **Mid-page CTAs.** The wireframe inserts a "JOIN US" CTA mid-page (between Overview and Who-It's-For). Keep, drop, or place differently?
- **Reusable vs per-trip content.** Best candidates for reuse: Section 12 (How to Book), Section 13 (Why Rockbusters), and the FAQ library. Worth a quick yes/no per item.
- **Coach card shape.** Trip Detail's wireframe uses a minimal coach card; Trip Category's uses a rich one (with bio + credentials). Standardise on one shape, support both, or always link out to a dedicated coach page?
- **Booking flow trigger.** Where does the JOIN US CTA actually go? Same booking form for every trip, or per-trip? Affects the hero booking-box design too.
- **Relationship to Trip Category page.** When this trip is part of a recurring program (e.g. a category page exists for it), how do the two pages link to each other?
